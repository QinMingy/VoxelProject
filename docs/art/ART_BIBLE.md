# 月面采掘 · 美术规范 v1
版本：2026-11-07。适用范围：本 Godot 项目的全部游戏画面、界面和对外美术。

**统一语言：原创 2D 像素精灵，置于可读、可交互的 3D 体素布景中。**
人物以手工整理的像素簇塑形；地形、建筑和需要环视/开采的实体用体素构建。空间感来自真实遮挡、脚底接触、克制的光照和前后景层次。单件资源请求也沿用本规范，不另起一套风格。

本文件锁定制作目标；当前程序化 3D 角色、圆角 UI 等仍是待迁移原型，**不能把规范完成当作运行画面已全部换装**。数值同步保存在 [style-lock.json](style-lock.json)，调色板可导入 [palette-v1.gpl](palette-v1.gpl)。

## 1. 保留的项目条件与假设

- 保留月面体素开采 → 返航 → 仓库整理/研究 → 展馆陈列的玩法、科技、经济和存档；大厅仍无可控主角，3 名观众自主参观。
- 已确认平台：Windows、横屏 Android；Godot GL Compatibility。现有设计视口 1100×720，同时验收 960×540、1600×720，Android 再检查 16:9 与 20:9 安全区。
- **假设**：尚未指定 Android 机型，先按中档设备 30 FPS、Windows 60 FPS 制订预算；这是目标，非性能或真机通过声明。
- 已确认人物身份来自用户的[角色参考](character-reference.png)：橙色金鱼、大眼与小圆嘴、圆形鱼缸头盔及可见水线、米白宇航服、橙色扣件、青色胸屏、深色靴子。保持这些特征，不能改成人脸/普通太空头盔。图中的旧侧视场景与 UI 不作为新场景模板。
- 原[展馆布局参考](museum-lobby-reference.png)只约束朴素地面、细分区线与重复展台；以运行中的 6 个展位为准，不增添新的玩法空间。

参考作品的官方介绍均描述了像素画与三维场景的结合：[歧路旅人 II](https://www.square-enix.com/asia/newsportal/en/sg/octopathii/)、[TRIANGLE STRATEGY](https://www.jp.square-enix.com/trianglestrategy/concept/)、[LIVE A LIVE](https://www.square-enix.com/asia/newsportal/en/topics/livealive/post01.html)。本项目从中研究前后景、人物可读性和光照组织；**体素限定是本项目自己的选择**，不声称复现这些作品的内部管线，不复制人物、标志、贴图或构图。

## 2. 先锁尺寸、镜头与 billboard

| 项目 | 锁定规格 |
| --- | --- |
| 世界单位/体素 | 1 单位 = 1 米；可交互体素保持 0.125 米；建筑按 0.125 米网格组合成 0.25/0.5/1 米模块 |
| 世界精灵密度 | **64 源像素/米**；1 个体素边长对应 8 个源像素。源像素指贴图像素，不是屏幕像素 |
| 玩家精灵 | 128×128 RGBA 单帧，整张卡片 2×2 m；常态人物可见高 80 px = 1.25 m；脚底锚点 (64,112)；所有动作共用画布/锚点 |
| 观众精灵 | 64×80 RGBA 单帧，整张卡片 1×1.25 m；常态人物可见高 60 px = 0.9375 m；脚底锚点 (32,72) |
| 小型装饰卡片 | 16/32/64 px 画布，按 64 px/m 解释；仅用于墙贴、非碰撞标牌、薄叶片等。不能把实体宝箱变成随视角转向的薄片 |
| 开采/展览物品 | 三维体素实体保持原尺寸、真实占格、磨损和碰撞；展示缩放沿用当前包围盒适配，不能为了图好看改变开采体积。手持工具的非碰撞外观可用 0.03125 m 细格（2 源像素），极细零件最低 0.015625 m，仍以体素塑形 |
| PNG/图集 | sRGB、无损 RGBA；主体 alpha 0/255；每帧四周 2 px 透明隔离，并给透明区填最近边缘 RGB；单图集≤2048² |
| 采样 | 放大使用 nearest；禁止自动平滑放大、锐化补边与全屏像素化。远处由同一源图派生、人工检查的离散 mip/LOD 简化细节，不换人物尺寸或随机颗粒密度 |

Billboard 卡片面向相机、保持画面竖直且不随相机 roll 翻转，**脚底是旋转中心**；不是把角色世界朝向改成对着玩家。方向图用角色与观察方位的相对角选择，45°一档、5°滞回；主角前向 −Z、观众前向 +Z 分别校准。主角俯仰分组界线为观察仰角 0°/30°，切组加 5°滞回；画图时分别校准 −15°/15°/47.4°，并在完整镜头范围验收。透视观察向量 v = 相机位置 −（角色脚底 + 世界UP×标准身高/2），仰角为 atan2(v.y, length(v.xz))；正交使用统一的相机反向视线（Godot camera.global_basis.z），不能直接拿相机 pitch 代替。水平分量小于向量长度5%时保持上一有效方位，避免垂直观察乱跳。

上表米制尺寸沿卡片平面计算，包含透明留白的整帧尺寸与人物可见高度必须分开；卡片倾斜后的世界Y向高度不是该值。卡片开启深度测试、透明裁切和有效深度写入；禁止借用文字标签的穿墙显示。碰撞盒与卡片分离：玩家原有 1.25 m 高、0.36 m 宽碰撞和脚底原点保持不变。卡片倾斜造成的墙角/头顶遮挡差异要在真实镜头中检查，不能用取消遮挡解决。

第一人称补充规格：左右手各用32×32源像素（0.5×0.5 m卡片），握点pivot=(16,16)；左右前臂各32×32，腕点pivot=(16,24)，均为64 px/m且不得左右镜像复用。手套轮廓约宽6–7、高5–6源像素；前臂长约13–14源像素，保持原rig比例。握点沿用 ToolPivot 局部左(-0.069,-0.049,-0.053)、右(0.066,-0.088,0.069)，腕点与对应握点配准；父pivot位置(0.30,-0.25,-0.52)、旋转(-0.21,0.14,-0.07)保持。待机1帧、开采4帧/12 FPS，接现有动画与命中事件。近景会把单源像素放大到十余屏幕像素，粗细和握持关系必须先做第一人称样例验收，不私自提高局部PPU掩盖问题。

**远近一致不等于屏幕像素恒定。** 正交屏幕密度 = 视口高度/正交视野；透视密度还随距离变化。保留固定世界大小与 64 px/m，接受正常透视缩放，不放大远处角色、不量化移动/碰撞、不为了整数放大改变镜头。验收目标是稳定轮廓、相同制作颗粒、脚底无漂移和远景无持续闪烁。

## 3. 调色、剪影与材质

24 色锁定的是源精灵、图标和体素基础色；灯光合成、阴影及可访问字体抗锯齿不计入源色数。每个角色通常使用 8–12 色，每种材质 3–4 档明度；不同批次不能擅自新增色板。

| 色阶用途 | 暗 → 亮 |
| --- | --- |
| 墨色/蓝灰结构 | #101C2A · #293346 · #46516B · #63738F |
| 月尘/米白 | #8A92A2 · #B9C2CE · #E2DECE · #FFF2DC |
| 铜锈/橙色识别 | #6A3D2B · #AD6134 · #EEA452 · #FFD29B |
| 青色设备/交互 | #194B59 · #2D8290 · #62C9C7 · #B6F1E0 |
| 紫晶/研究 | #44345F · #7851A9 · #B875ED · #E4B9FF |
| 肤色/低氧警示 | #633C47 · #B76062 · #D79A86 · #F2C6A5 |

- 主角：80 px 可见身高中，鱼缸轮廓占 42–44 px；大头盔、短身躯、厚靴组成三段剪影。保留鱼鳍与水线，胸屏只用一个清楚色块。以参考身份为准，不追求每个小铆钉。
- 观众：60 px 可见身高、头部 18 px；发型/帽子与肩线区分三人，衣色只用辅助色阶。不能给每个 NPC 一种不同的绘画精度。
- 主体轮廓 1 源像素深色断续描边；高光处可断开。禁止统一厚黑框；重要识别点至少 2×2 源像素，删除孤立噪点。
- 石土：蓝灰 3 档、大片面、可见体素断面，无照片纹理；展台金属：蓝灰侧面+米白顶面+少量橙色标牌，低反光、无镜面地板。
- 晶石：紫色 3–4 档、阶梯晶簇，亮点每簇 1–2 处；木箱/旧遗物：铜锈色大块分面，磨损沿体素面成簇，禁止细密随机刮痕。
- 头盔玻璃：在精灵内用两级青白像素高光和水线表达；不做扭曲背景的实时折射。3D 透明物优先少量体素色片，不叠多层透明壳。

## 4. 光照、UI、动效与对外画面

| 类别 | 统一规则 |
| --- | --- |
| 光照层次 | 环境用低饱和冷蓝；一盏暖主光确定体素明暗；展品/交互点才允许青/紫局部光。主光方向场景内固定，画面不能处处发亮 |
| 精灵融入 | 源图避免烘死强方向投影；用≤3 档亮度响应与最多一盏附近灯的轻染色，颜色偏移幅度以约±15%为起点。不得把角色整张照黑或高光漂白 |
| 阴影/反射 | 体素接收场景阴影；角色用跟随地面法线的像素接触影，范围不超身体宽度1.3倍，透明度20–35%。不让一张直立卡片投出长方形影子；地面反射默认关闭 |
| 景深/后处理 | 游戏过程景深、运动模糊、TAA 拖影关闭；沿用现有 GL 路径。宣传图若使用景深，只作用远背景，1080p 模糊半径≤1 px，人物/工具/可交互轮廓排除 |
| UI/气泡 | 深蓝面板、米白正文、橙色主行动、青色选中；2 px 阶梯角、1–2 px边框、2–4 px下沿形成轻微厚度；气泡米白底深字、小三角尾。背景像素化不等于把文字低清化 |
| 字体/目标 | 中文正文≥18逻辑px，按钮/关键数值20–24，辅助字≥16；点击区≥48×48逻辑px、间距≥8。颜色之外再用形状/文字表示选中、锁定与危险 |
| 图标 | 工具/菜单原稿24×24，物品32×32，人物头像64×64；同类别同画布、同1 px描边，优先按2×整数尺寸显示，低分辨率另做简化稿而非糊缩 |
| 特效 | 像素尘团、方块碎屑、2–3档颜色闪光；主体实心、边缘裁切，不以大片半透明烟雾遮矿点。单效果4–6帧，0.15–0.4秒；减弱特效模式保留命中提示 |
| 加载画面 | 使用同一体素世界和像素人物；角色身份/色板/比例不变。小循环6帧、8 FPS；真实进度与可读提示独立UI层，不画虚假进度 |
| 宣传图 | 从相同体素布景与批准精灵组织原创构图；1920×1080交付，保留安全裁切区与分层源文件。标题自行排版，不生成仿制 logo，不换写实脸/写实场景来“提质” |

固定文字配色的计算对比度：米白 #FFF2DC / 墨底 #101C2A = 15.54:1；浅石 #B9C2CE / 深蓝 #293346 = 7.05:1；墨字 / 橙按钮 #EEA452 = 8.24:1。以上仅为不透明sRGB基础色在线性化后按相对亮度(L亮+0.05)/(L暗+0.05)的计算值；实际场景叠底、半透明面板及全部交互状态必须重新测量。文字目标≥4.5:1，交互边界≥3:1；禁用态也保留可读标签，红绿不作为唯一编码。

动作不补光流中间帧、不对像素贴图做软变形：待机4帧/6 FPS，步行6帧/10 FPS，采掘6帧/12 FPS，拾取4帧/10 FPS；移动仍按原游戏连续计算，步行相位跟随实际路程。静止/原地动作脚底锚点漂移≤1源像素，方向切换不缩放身体、不镜像带有左右差异的装备。跳跃保留现有轨迹，手部打击帧与原命中时机对齐。气泡仍每7–11秒最多出现一条、约4秒后消失，换展立即换评价来源。

## 5. 每批交付与验收

**初始资源预算（须实测）**：可见观众仍3名；单图集≤2048²；角色/UI/特效常驻未压缩纹理合计≤64 MiB；一盏投影主光、最多两盏不投影局部灯、同时活跃小粒子≤48。超预算先减装饰粒子/灯和重复图集，不降低中文可读性或删脚底阴影。Android 必须单独测量，不拿桌面截图替代。

每批必须附：规范版本、参考文件、原尺寸 PNG、可编辑分层源、图集与逐帧元数据、色表、PPU、脚底 pivot、朝向组、帧顺序/FPS、碰撞独立声明、导出/导入设置和验收截图。主角后续生产先做方向与俯仰基准页，再批量动作；大厅 NPC 只需俯视组，月面主角的三组八方向会明显增加绘制量，不能靠一张正面图完成。

交付前在实际游戏中检查：960×540 / 1100×720 / 1600×720；空馆/满馆；仓库旋转两端；月面近/中/远距离、俯仰端点、镜头被墙拉近、遮挡和跳跃；字体与触点、静止像素闪烁、脚底位置、气泡越界。源图按1×与最近邻4×查看，最终判断还必须回到原生显示尺寸。未过的条目写明“待验收”，不得以预览图代替可用精灵表。

**避免的错误**：大景深遮丑；高清照片/光滑写实模型混入体素；每批像素密度不同；把人物体素化来冒充2D精灵；远处角色被放大；精灵穿墙/漂浮/背面突然变正面；双线性糊边/缩放闪烁；换装改变金鱼身份；HUD小字硬做像素字；未审校的AI图直接当精灵表。

迁移顺序：观众像素基准与实际大厅 → 主角方向/俯仰基准及第一人称手部 → 体素材质和选定薄道具 → UI/图标/特效 → 加载/宣传。各阶段沿用本锁定规范；先通过一组可玩样例再铺量。现有玩法、镜头、碰撞、存档接口保持。

后续资源请求的固定说明：
> 使用《月面采掘美术规范 v1》：原创2D像素精灵与3D体素布景，64源像素/米、0.125米世界体素、24色基础色表、明确脚底锚点与方向组；按当前镜头和实际显示尺寸验收。保留已确认角色身份及玩法用途，不另换风格。
